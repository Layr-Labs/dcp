## 1. Literal FWLEVEL control and its exact macro channel

P virtual7.2 specifies exactly rounds=q(Y+1) iterations. Every iteration sorts LIVE by KEY, scans each equal-key run into full w-groups, executes FW on each group, puts returned/recycled qubits and ungrouped qubits in next LIVE, and appends good outputs to OUTPUT. Only AFTER the last iteration is all remaining LIVE measured, reset and released. FWLEVEL is called in P virtual2(7.3), always with Cin=D=2^cb and followed by the SAME OUTPUT>=Yd guard.

The actual compiler uses the same literal sort, run scan, grouping, FW words and output/returned-handle transfers for each executed round. Initialize one ordinary staged group flag to0 before the scan; set it to1 when the scan encounters a full w-group. The existing scan already obtains run lengths/groups, so this needs no additional pass over an array. Complete the entire current round. If the flag is1, do the normal next-round test. If the flag is0, jump to the original final LIVE measurement/reset/release, then return the same OUTPUT. A source-local round counter, if its terminal value is needed by the compiled return, is written once to that public terminal value with a charged WORD operation. The loop/capture continuation is popped exactly as on ordinary loop exit. No extra source call, quantum gate, copied unknown state, failure guard or persistent array is added. The flag fits the constant staged/control-reserve inventory. Every added flag test, counter write, PC update and return is paid at the complete prefix's global address fee.

Suppose the just-completed round has no full w-group. It has executed NO FW, therefore no PREP, quantum gate, measurement or FW abort; OUTPUT is unchanged. Its next LIVE consists of exactly the same labeled qubits, now merely sorted and copied into the normal LIVE representation. Every run has size<w. Since no quantum/label operation occurs, its key multiset is unchanged. Every subsequent original round also has no full group, so it has the same property. This remains true even if a deterministic merge-sort tie policy permutes equal-key records differently on repeated sorts: no run's cardinality changes, no FW is executed, and every remaining LIVE qubit is discarded at the end.

For an arbitrary joint state on LIVE, OUTPUT, other P data and a reference, the repeated empty rounds act only on classical record/handle representation. They do not act on the mapped quantum states or OUTPUT and do not acquire a source. The final full LIVE discard is a partial trace followed by the specified reset/disposal; it is invariant under the order in which those same subsystems are discarded. Thus the COMPLETE reference FWLEVEL OUTPUT/data/reference channel equals the physical shortened FWLEVEL channel. Both execute exactly the same productive FW prefix with the same outcomes, and then discard precisely the same LIVE systems. They return identical OUTPUT labels/handles/length. In particular the caller's under-yield ABORT decision, run caps and all later source requests have the same law.

## 3. Recursive pool, FW rounds and fixed helpers

All pool sizes D_i are the SAME D=2^cb in virtual2(7.3). A FWLEVEL run has at most D/2 outputs. A buffer starts empty; immediately after returning D qubits, it has fewer than D/2 left: before its last append it held<D, the append has size<=D/2, and then D is removed. Every COMPLETED REQUEST therefore executes at least one own local FWLEVEL run, in fact at least two, in addition to obtaining its input chunk recursively. It cannot complete as a chain of merely forwarding a child call without local work.

Only a FW can create an OUTPUT qubit, so that run executed its own FW core word.
